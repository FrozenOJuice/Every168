## Deployment handoff

Follow [PUBLIC_BETA_DEPLOYMENT.md](PUBLIC_BETA_DEPLOYMENT.md). Recommended architecture: one Linux VM with TLS reverse proxy, Next.js and one loopback-bound Express process; private managed PostgreSQL; Resend for account emails. Keep a single API instance while limits remain process-local.

Owner configuration/acceptance still required:

- Hostname/DNS/TLS, host firewall, service supervision and edge forwarding-header policy.
- Restricted runtime DB identity, separate migration credential, verified database TLS and migration/rollback procedure.
- Resend key, verified sender/DNS and real signup/reset inbox delivery.
- Encrypted off-host backups, retention/alerts and a timed isolated restore against the chosen infrastructure.
- External health/error/backup monitoring, support/privacy expectations and an authorized operator/account-deletion process. Production Admin provisioning remains separately authorized; the current local helper must not be pointed at production.
- Real-host synthetic account isolation, Calendar/Fitness end-to-end, restart/retry and mobile/keyboard acceptance.

`pnpm verify:beta` supplies the ordered application gate. The built-web smoke has a separate production config documented in verification.md. Actual deployment, secrets, paid infrastructure and production acceptance remain outside this authorization.
