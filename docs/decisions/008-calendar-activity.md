# Calendar day activity

The owner authorized Calendar as a daily overview of plans, recorded sessions and point-in-time moments, plus a simpler composer. Custom/public domains remain future work.

Each existing domain exposes a public `calendarActivity(userId, range)` projection. Food, Hydration and Body supply moments; Strength and Cardio supply sessions. The common contract carries source identity, domain label, icon name, kind/status, occurrence/end instants, title, summary and an internal source link. Unknown icon names use a neutral fallback. Calendar renders these properties without rules for individual log types. Adding a source means registering its public provider in composition, rather than teaching Calendar what its records mean.

The Planning activity service resolves the account's timezone-correct date range and composes public providers. Persistence remains in each module's repository, scoped to the authenticated user. The API accepts at most 42 dates of separation, matching existing Calendar range semantics. Each source returns at most 200 entries, ordered by occurrence time and ID, and reports truncation. Full histories remain in their domains. Day view and day dialogs request the selected date separately so month limits do not truncate an ordinary day review. No activity-feed table, write duplication, background processing or schema changes were introduced. Read failures are recoverable and never presented as an empty activity history.

Moments have no end or accounting duration. They never create time entries. Exercise retains its canonical one-source/one-time-entry writes. The day feed uses source identities to suppress the matching accounting entry when its richer domain session is present. Plans stay explicitly planned, including after their scheduled time passes. Draft workouts are labelled unfinished rather than inferred to be current/completed sessions.

Day view combines the time grid with an ordered Earlier/Now/Coming up feed and a short current/next overview. Date-only plans remain separate. Repeated moments from the same source in an hour collapse behind an accessible disclosure. Week grid shows moment counts and compact hour markers; Month includes moment counts. The day feed provides source links. Clock-change days keep the existing exact-time fallback; moment entries include timezone labels.

The Add composer opens directly to a short plan form; category, goal and notes sit behind More details. Record offers the existing domain forms or manual time. Clicking a slot carries its local date/time into any selected recording form. Toolbar recording defaults use the existing date-aware logging helper. All-day, unscheduled and repeating plans remain available. Pending or uncertain saves lock mode/type changes and dismissal, retaining the original payload/key for retry. Domain mutations invalidate composed activity reads alongside their own caches.

Existing Week defaults, drag/resize/copy/templates, ownership, revisions, snapshots and canonical time accounting remain in place. Global history search continues searching plans and time entries; domain moments are visible through date views and their source histories.
